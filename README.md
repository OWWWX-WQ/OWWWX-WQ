## Research Approach

1. Establish explicit authorization and scope.
2. Record normal application and transaction behavior.
3. Develop falsifiable security hypotheses.
4. Use controlled accounts, orders, and synthetic data.
5. Preserve reproducible, redacted evidence.
6. Stop at proof of impact.
7. Provide root-cause fixes and measurable retest criteria.

## Technical Practice

My work commonly involves HTTP request and response analysis, browser developer tools, Burp Suite, Python-based test automation, API review, controlled replay testing, negative controls, and structured security reporting.

## Responsible Research

All published work is limited to authorized CTF, laboratory, self-owned, or explicitly approved assessment environments. Live target identifiers, credentials, signing secrets, customer data, payment identifiers, and operational exploit payloads are not published.
